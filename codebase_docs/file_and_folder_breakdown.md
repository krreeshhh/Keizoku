# Keizoku Codebase — Exhaustive File & Folder Architecture Breakdown

## 1. Executive Architecture & Directory Topology

Keizoku is a professional, privacy-first, ad-free, telemetry-free strength training, workout tracking, and fitness analytics application engineered with Flutter & Dart for Android, iOS, and Wear OS. The codebase combines zero-latency local state mutation and atomic disk persistence with a cloud-connected online subsystem powered by Google Firebase.

### Architectural Pillars

1. **Hybrid Offline-First & Online Community Model**:
   - **Local Storage Primacy**: The application operates completely offline without network connectivity. Local workouts, body measurements, gym notes, and user configurations are committed atomically to `fit_state.json` via `LocalStore.instance` with debounce protection.
   - **Firebase Online Integration**: The codebase includes `firebase_core`, `firebase_auth`, and `cloud_firestore` configured via `firebase_options.dart` and `firebase.json`.
   - **Anonymous Authentication**: Automatic passwordless identity bootstrapping on startup via `FirebaseAuth.instance.signInAnonymously()`. Every device is assigned a cryptographic Firebase UID without asking the user for email, password, or third-party OAuth logins.
   - **Unique Handle Claiming Engine**: Global athlete identification using unique `@handle` identifiers. Claiming uses atomic Firestore transactions (`runTransaction`) against the `handles` collection with real-time conflict checking and debounced availability checks in onboarding and profile editing.
   - **Secret Recovery Backup Code**: Every profile generates a cryptographically random 13-character recovery code in `GYM-XXXX-XXXX` format (`SettingsState.generateBackupCode()`). This code is linked to the claimed handle in Firestore and enables zero-password account recovery across devices (`restoreAccountWithBackupCode()`).
   - **Social & Community Hub**: Real-time athlete search by handle, incoming and outgoing friend request streams, mutual friend relationships with live streak tracking, and local offline friend caching (`cached_friends` in `LocalStore`).
   - **Community Routines Hub**: Public routine sharing with unique 6-character alphanumeric share codes (e.g., `GYM-8X2A`), real-time streaming of community-shared routines, and one-tap import into the local routine library with author attribution.
   - **GDPR & Cloud Account Wipe**: Full remote data purge (`deleteAccountAndAllData()`) deleting user profiles, claimed handles, mutual friendships, friend requests, and authored routines from Firestore, accompanied by local state wipe (`fit.resetAllData()`).

2. **Strict Privacy Boundary**:
   - Biometric physique progress photos, training moments snapshots, avatar images, and custom wallpaper backgrounds are **strictly stored on-device** via `MediaStore` within the application sandboxed storage.
   - Media files are **never uploaded to Firebase or any external cloud service**. Only lightweight workout metadata, routine blueprints, streak counts, and handle records are synchronized.

3. **Native Android Platform Bridges**:
   - **Home Screen AppWidgets**: Android AppWidgets (`HeatmapWidgetProvider`, `StatsWidgetProvider`, `TodayWidgetProvider`, `WeekWidgetProvider`, `BodyWidgetProvider`) updated via `HomeWidgetBridge` using offscreen rasterized Flutter views (`home_widget_views.dart`).
   - **Ongoing Live Workout Foreground Service**: Background workout timer and notification maintenance via Kotlin `LiveNotifier` and `ScreenAwake`.
   - **Strava / Garmin FIT Export**: High-performance binary FIT protocol encoder (`fit_export.dart`) generating standard `.fit` files for workout sharing to Strava.

4. **Wear OS Smartwatch Subsystem**:
   - Standalone smartwatch application (`WearApp`) and interactive session shell (`WearShell`).
   - Native rotary input support (`WearRotary` listening to method channel `keizoku/rotary` for rotating crowns on Pixel Watch and Galaxy Watch).
   - Low-power ambient display mode and circular AMOLED layout optimizations.

5. **Modern Glassmorphic & Brutalist Design System**:
   - Bespoke styling system (`AppTheme`, `GymColors`, `GlassSurface`, `LiquidNotch`, `ExpressivePressable`).
   - Dual typography scale conventions: primary display font `Darker Grotesque` scaled at `1.18`, and monospace numerical font `Space Mono` scaled at `1.08`.
   - Pure OLED Black theme mode (`oled = true`) for maximum battery savings on AMOLED displays.

## 2. Root Project Configuration & Environment Files

The root repository contains build manifests, dependency resolutions, static analysis definitions, translation configs, Firebase setup, and legal terms that govern the repository.

### `.flutter-plugins-dependencies`
- **Path**: `.flutter-plugins-dependencies`
- **Exact Purpose**: Machine-generated plugin dependency map generated by Flutter tooling. Caches installed Flutter plugins and their native platform integration paths (including `audioplayers`, `file_picker`, `flutter_local_notifications`, `home_widget`, `image_picker`, `path_provider`, `share_plus`, `shared_preferences`, `url_launcher`, `video_player`, `dynamic_color`, `firebase_core`, `firebase_auth`, `cloud_firestore`).
- **Primary Elements**: JSON object detailing plugin paths, platforms, and native plugin class bindings.
- **Key Responsibilities**: Enables Flutter tooling and native build systems (Gradle/Xcode) to discover platform-specific implementations without re-parsing `pubspec.yaml` on every build step.
- **Invariants & Interactions**: Auto-regenerated by `flutter pub get`. Must never be edited manually.

### `.gitignore`
- **Path**: `.gitignore`
- **Exact Purpose**: Specifies intentionally untracked files and directories that Git ignores across Dart, Flutter, Android, iOS, and development tools.
- **Primary Elements**: Patterns ignoring `.dart_tool/`, `build/`, `.idea/`, `*.iml`, `.flutter-plugins*`, `android/local.properties`, `android/.gradle/`, and transient export archives.
- **Key Responsibilities**: Prevents binary caches, personal developer paths, signing keys, and temporary build outputs from polluting version control.
- **Invariants & Interactions**: Ensures clean repository clones across contributors on Linux, macOS, and Windows.

### `.metadata`
- **Path**: `.metadata`
- **Exact Purpose**: Internal Flutter project descriptor file used by the Flutter SDK to track project type and migration version.
- **Primary Elements**: YAML-based tracking of `version: 2`, `project_type: app`.
- **Key Responsibilities**: Informs Flutter tooling that this directory represents an application rather than a package, plugin, or module, guiding `flutter upgrade` migrations.
- **Invariants & Interactions**: Managed exclusively by the Flutter CLI.

### `ADDITIONAL_TERMS.md`
- **Path**: `ADDITIONAL_TERMS.md`
- **Exact Purpose**: Legal stipulations supplementing the GNU General Public License v3.0, specifically covering trademark protections, commercial re-distribution, and brand assets.
- **Primary Elements**: Clauses regarding the name "Keizoku", application logo rights, proprietary iconography, and restrictions on re-publishing identical clones to app stores under the official branding without explicit permission.
- **Key Responsibilities**: Protects project identity and user trust against malicious clones while maintaining complete open-source code freedom under GPLv3.
- **Invariants & Interactions**: Directly referenced in `AboutScreen` and GitHub distribution documentation.

### `CONTRIBUTING.md`
- **Path**: `CONTRIBUTING.md`
- **Exact Purpose**: Onboarding guide and development standards for open-source contributors and bug reporters.
- **Primary Elements**: Code formatting rules (`dart format`), static analysis expectations (`flutter analyze`), architectural guidelines (ChangeNotifier state patterns, zero network telemetry, privacy primacy), pull request conventions, and instructions for contributing exercises and translations.
- **Key Responsibilities**: Streamlines community contributions and enforces zero regression in performance, battery consumption, and privacy.
- **Invariants & Interactions**: Enforces running `flutter test` before submitting changes.

### `LICENSE`
- **Path**: `LICENSE`
- **Exact Purpose**: Full legal text of the GNU General Public License v3.0 (GPLv3).
- **Primary Elements**: 35 KB document detailing the terms and conditions for copying, distribution, modification, patent grants, and source code availability under copyleft.
- **Key Responsibilities**: Ensures Keizoku remains permanently free and open-source software, mandating that any derivative work or modification must also release its full source code under GPLv3.
- **Invariants & Interactions**: Referenced by `AboutScreen` via `showLicensePage()` or in-app about modals.

### `README.md`
- **Path**: `README.md`
- **Exact Purpose**: The repository front page providing project introduction, showcase imagery, philosophy, installation methods, and feature index.
- **Primary Elements**: Badges (F-Droid, GitHub Releases, Obtainium, license, Flutter version), high-resolution UI screenshots, detailed list of capabilities (offline logging, 400+ exercises with ASCII art/media, 1RM calculators, plate math, custom routines, Wear OS app, privacy policy, Firebase social sync and routine sharing), building instructions, and cryptocurrency support addresses.
- **Key Responsibilities**: Acts as the primary landing page for developers and end-users discovering the project on GitHub.
- **Invariants & Interactions**: Maintained as clean plain markdown without embedded promotional images.

### `TRANSLATING.md`
- **Path**: `TRANSLATING.md`
- **Exact Purpose**: Detailed instructions for translators on how to localize Keizoku into foreign languages.
- **Primary Elements**: Guide for editing ARB files (`lib/l10n/app_*.arb`), working with Crowdin, catalog translation files (`catalog_*.dart`), rules for grammatical gender/plurals, and running `flutter gen-l10n`.
- **Key Responsibilities**: Empowers non-technical multilingual contributors to expand Keizoku's international accessibility without breaking JSON syntax.
- **Invariants & Interactions**: Works in tandem with `l10n.yaml` and `crowdin.yml`.

### `analysis_options.yaml`
- **Path**: `analysis_options.yaml`
- **Exact Purpose**: Static analysis rules, lint configurations, and compiler diagnostics for Dart and Flutter.
- **Primary Elements**: Inherits from `package:flutter_lints/flutter.yaml`. Customizes specific lints (const constructor enforcement, avoiding print statements, preferring final fields, controlling cast rules).
- **Key Responsibilities**: Guarantees consistent code style, prevents accidental memory leaks, enforces null-safety best practices, and minimizes runtime exceptions.
- **Invariants & Interactions**: Checked on every commit and CI run via `flutter analyze`.

### `crowdin.yml`
- **Path**: `crowdin.yml`
- **Exact Purpose**: Configuration file for the Crowdin CLI localization automation service.
- **Primary Elements**: Specifies project ID, API token environment variables, source file patterns (`lib/l10n/app_en.arb`), and target path mappings (`lib/l10n/app_%two_letters_code%.arb`).
- **Key Responsibilities**: Synchronizes English string additions to the Crowdin translation platform and automatically pulls community translations back into the repository.
- **Invariants & Interactions**: Must match language codes defined in `l10n.yaml`.

### `firebase.json`
- **Path**: `firebase.json`
- **Exact Purpose**: Firebase CLI configuration mapping cloud services to local platform artifacts.
- **Primary Elements**: Configuration blocks for `flutter` (target configurations, file outputs like `lib/firebase_options.dart`) and Firestore security rules / schema configurations.
- **Key Responsibilities**: Enables `flutterfire configure` to generate consistent credentials for cloud authentication, handle claiming, friend streams, and routine sharing.
- **Invariants & Interactions**: Drives compilation of `firebase_options.dart` and integrates with `FirebaseService`.

### `l10n.yaml`
- **Path**: `l10n.yaml`
- **Exact Purpose**: Flutter's native localization tool configuration file.
- **Primary Elements**: 
  - `arb-dir: lib/l10n`
  - `template-arb-file: app_en.arb`
  - `output-localization-file: app_localizations.dart`
  - `untranslated-messages-file: untranslated.json`
- **Key Responsibilities**: Instructs `flutter gen-l10n` where to read localized message definitions and where to generate strongly-typed Dart accessor classes.
- **Invariants & Interactions**: Drives the generation of `lib/l10n/app_localizations*.dart`.

### `pubspec.yaml`
- **Path**: `pubspec.yaml`
- **Exact Purpose**: Project definition, environment constraints, third-party dependency declarations, and asset bundle registrations.
- **Primary Elements**:
  - App metadata: `name: keizoku`, `version: 1.0.0+1`, `sdk: ^3.11.5`.
  - Core dependencies: `audioplayers: ^6.1.1`, `cupertino_icons: ^1.0.8`, `file_picker: ^8.1.7`, `flutter_local_notifications: ^18.0.1`, `home_widget: ^0.7.0`, `image_picker: ^1.1.2`, `intl: ^0.20.2`, `path_drawing: ^1.0.1`, `path_provider: ^2.1.5`, `phosphoricons_flutter: ^1.2.0`, `share_plus: ^10.1.4`, `shared_preferences: ^2.5.2`, `timezone: ^0.10.0`, `url_launcher: ^6.3.1`, `video_player: ^2.9.2`, `archive: ^4.0.2`, `app_settings: ^5.1.1`, `dynamic_color: ^1.7.0`, `firebase_core: ^3.12.0`, `firebase_auth: ^5.5.0`, `cloud_firestore: ^5.6.4`.

- **Invariants & Interactions**: Modifying requires running `flutter pub get` and updating `pubspec.lock`.

### `pubspec.lock`
- **Path**: `pubspec.lock`
- **Exact Purpose**: The immutable snapshot of every direct and transitive package dependency pinned to an exact cryptographic commit/version hash.
- **Primary Elements**: YAML file pinning ~100 transitive packages (including `crypto`, `vector_math`, `meta`, `stream_channel`, etc.).
- **Key Responsibilities**: Guarantees deterministic, reproducible builds across developer machines, CI/CD runners, and automated build servers.
- **Invariants & Interactions**: Committed to source control; updated only via `flutter pub upgrade`.

## 3. Top-Level Root Files (`lib/`)

The root `lib/` directory contains the application entrypoint and platform-wide initialization configurations.

### `lib/main.dart`
- **Path**: `lib/main.dart`
- **Exact Purpose**: Application execution entrypoint. Orchestrates device detection, services bootstrap, state initialization, and app launch.
- **Primary Functions & Flow**:
  - `main()`: Calls `WidgetsFlutterBinding.ensureInitialized()`.
  - Detects whether the host hardware is a Wear OS watch via `DeviceKind.isWear()`.
  - Initializes `LocalStore` via `Store.instance.init()` and loads persistent state into global singleton `fit`.
  - Registers `RestAlarm` audio players, notification channels via `FlutterLocalNotificationsPlugin`, and timezone databases.
  - Sets up `HomeWidgetBridge` to update Android native AppWidgets with initial metrics.
  - Boots optional Firebase features conditionally (using `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`). Initializes `FirebaseService.instance.initialize()` for anonymous auth and handle setup.
  - Launches `WearApp` if running on a smartwatch, otherwise runs `KeizokuApp`.
- **Key Responsibilities**: Single gatekeeper for cold-start initialization, ensuring critical local databases and audio drivers are ready before the first UI frame paints.
- **Invariants & Technical Details**: Must handle asynchronous initialization failures gracefully to allow offline execution even without network access or cloud services.

### `lib/firebase_options.dart`
- **Path**: `lib/firebase_options.dart`
- **Exact Purpose**: Auto-generated platform configuration mapping Firebase credentials to Android, iOS, macOS, and Web targets.
- **Primary Classes**: `DefaultFirebaseOptions`.
  - `currentPlatform`: Static getter returning `FirebaseOptions` based on `defaultTargetPlatform`.
  - `android`: Firebase options (API key, App ID, Messaging Sender ID, Project ID, Storage Bucket) for Android builds.
  - `ios`: iOS configuration options bundle.
- **Key Responsibilities**: Provides type-safe credentials to `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`.
- **Invariants & Technical Details**: Generated by the FlutterFire CLI; contains project public identifier tokens.

  - Dispatches global navigation between `AppShell` and full-screen overlays (active live workout session).
- **Invariants & Technical Details**: Sets up custom scroll physics and prevents unnecessary MaterialApp rebuilds by memoizing theme objects.

### `lib/app/app_shell.dart`
- **Path**: `lib/app/app_shell.dart`
- **Exact Purpose**: The master navigation shell holding the persistent bottom navigation bar, floating "Liquid Pill", parked active workout widget, and indexed stack for primary tabs (938 lines).

  - Manages primary application navigation stack without destroying screen state (using lazy caching and Offstage / IndexedStack rendering).
  - Houses the persistent active workout indicator allowing seamless navigation to exercise libraries or settings while mid-workout.

## 5. Exercise Catalog & Program Templates (`lib/catalog/`)

The `lib/catalog/` directory represents the static domain knowledge base of Keizoku, containing the database of 400+ built-in exercises, vector muscle maps, muscle hierarchy definitions, international aliases, external OpenGym ID cross-references, and pre-packaged workout program templates (PPL, Arnold Split, Upper/Lower, Calisthenics progressions).

### Directory Role & Architecture
- **Path**: `lib/catalog/`
- **Core Purpose**: Acts as the immutable reference library for exercises, muscle anatomy, and structured training routines.
- **Interactions**: Consumed by `LibraryState`, `ExercisesScreen`, `ExerciseDetailScreen`, `MuscleRadarCard`, `BodyMap`, and `WorkoutState`. Pure Dart data structures without mutable state.

---

### `lib/catalog/body_svg.dart`
- **Path**: `lib/catalog/body_svg.dart`
- **Exact Purpose**: Contains raw SVG path data strings and coordinate systems for rendering anatomical human body maps (front and back views) across all major muscle groups.
- **Primary Elements**:
  - Constant SVG path maps: `kBodySvgFront`, `kBodySvgBack`.
  - Muscle group path IDs: Chest, lats, traps, front delts, lateral delts, rear delts, biceps, triceps, forearms, abs, obliques, quads, hamstrings, glutes, calves, and lower back.
  - Normalized canvas dimensions (based on a standard anatomical viewport).
- **Key Responsibilities**: Feeds path definitions to `lib/widgets/body_map.dart` for custom `PathParser` and `Canvas.drawPath()` rendering.
- **Invariants & Technical Details**: Paths are strictly normalized so that individual muscle polygons can be filled with dynamic heat colors independently based on recovery status or fatigue volume.

---

### `lib/catalog/exercise_aliases.dart`
- **Path**: `lib/catalog/exercise_aliases.dart`
- **Exact Purpose**: Exhaustive lookup map of synonyms, colloquial gym terms, foreign naming variants, and alternative spellings for exercises.
- **Primary Elements**:
  - `kExerciseAliases`: Map of canonical exercise IDs / names to lists of alias keywords (e.g. "RDL" -> "Romanian Deadlift", "Skull Crusher" -> "Lying Triceps Extension", "Military Press" -> "Overhead Press").
- **Key Responsibilities**: Powers fuzzy search in `exercise_match.dart` and ensures user searches for shorthand terms land on the correct canonical exercise.
- **Invariants & Technical Details**: Aliases are lowercase-normalized; tested in `test/exercise_alias_test.dart`.

---

### `lib/catalog/exercise_catalog.dart`
- **Path**: `lib/catalog/exercise_catalog.dart`
- **Exact Purpose**: The master database containing 400+ built-in strength training exercises.
- **Primary Elements**:
  - `kExercises`: Immutable `List<Exercise>` defining each movement's `id`, `name`, `primary` muscle, `secondary` muscles, `equipment`, `difficulty`, `art` (reference to ASCII vector file), and step-by-step instructions (`steps`).
  - `kMuscles`: Master list of muscle definitions with localized display labels and body views.
  - `kEquipment`: Master set of supported equipment types: `Barbell`, `Dumbbell`, `Kettlebell`, `Machine`, `Cable`, `Band`, `Bodyweight`, `Weighted`.
- **Key Responsibilities**: Forms the static core of Keizoku's exercise library.
- **Invariants & Technical Details**: Exercise IDs are fixed 7-character alphanumeric tokens (e.g. `EIeI8Vf`, `SpYC0Kp`) guaranteeing stable references across migrations and exports.

### `lib/services/firebase_service.dart`
- **Path**: `lib/services/firebase_service.dart`
- **Exact Purpose**: Complete cloud synchronization, anonymous authentication, unique handle claiming, recovery backup codes, social friend streams, community routine hub, and GDPR account wipe coordinator (872 lines).
- **Primary Classes**: `FirebaseService` (singleton instance `firebaseService`).
- **Core Subsystems & Methods**:
  1. **Initialization & Anonymous Authentication**:
     - `initialize()`: Boots Firebase via `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`. Configures Firestore offline persistence:
       ```dart
       _firestore.settings = const Settings(
         persistenceEnabled: true,
         cacheSizeBytes: Settings.CACHE_SIZE_UNLIMITED,
       );
       ```
     - Silently signs in anonymously via `_auth.signInAnonymously()` if no active user exists. Assigns a cryptographic Firebase UID without requiring email, password, or third-party sign-in.
  2. **Unique Handle Claiming Engine**:
     - `isHandleAvailable(String handle)`: Queries Firestore `handles/{cleanHandle}` document to verify availability or existing ownership by `currentUid`.
     - `isCurrentHandleClaimedByOther()`: Verifies if user's local handle is claimed by a different UID.
     - `claimHandle(String requestedHandle)`: Executes an atomic Firestore transaction (`_firestore.runTransaction`):
       - Verifies availability in `handles/{cleanHandle}`.
       - Releases old handle doc if changing handle.
       - Claims target handle doc with fields `uid`, `handle`, `backupCode`, and `claimedAt: serverTimestamp()`.
       - Updates `users/{currentUid}` with `handle` and `backupCode`.
  3. **Profile & State Synchronization**:
     - `syncUserProfile()`: Synchronizes user metadata to Firestore `users/{currentUid}`:
       - Profile: `uid`, `handle`, `displayName`, `badge`, `streak`, `maxStreak`, `weeklyGoal`, `workoutsCompleted`, `lastWorkoutDate`.
       - Biological baselines: `sex`, `age`, `heightCm`, `weightKg`, `units`.
       - Routines: Full `fit.routines` serialized to JSON.
       - Custom exercises: Full `fit.customExercises` serialized to JSON.
       - Weekly plan: `fit.weeklyPlan` schedule map.
       - Account credentials: `backupCode` (`GYM-XXXX-XXXX`).
       - Timestamp: `lastSync: serverTimestamp()`.
     - Also keeps `handles/{cleanHandle}` in sync with the current backup code.
     - **Privacy Boundary**: Profile avatar photo and banner background are **strictly excluded** from sync and remain on-device only.
  4. **Social & Friend Relationships**:
     - `searchUsersByHandle(String query)`: Performs prefix search on `users` collection (`handle >= clean` and `handle <= clean`, limit 15), excluding the current user.
     - `sendFriendRequest(UserProfileOnline target)`: Creates document in `friend_requests/${currentUid}_${target.uid}` with `FriendRequest` data.
     - `acceptFriendRequest(FriendRequest req)`: Uses Firestore batch write to create mutual friendship records in `users/{currentUid}/friends/{targetUid}` and `users/{targetUid}/friends/{currentUid}`, then deletes the request doc.
     - `declineFriendRequest(FriendRequest req)`: Deletes invitation doc from `friend_requests`.
     - `removeFriend(String friendUid)`: Batch deletes mutual friendship documents from both users' `friends` subcollections.
     - `streamIncomingRequests()`: Real-time `Stream<List<FriendRequest>>` of pending requests where `toUid == currentUid`.
     - `streamSentRequestUids()`: Real-time `Stream<Set<String>>` of UIDs to whom the current user sent pending requests.
     - `streamFriends()`: Real-time stream of `users/{currentUid}/friends` subcollection. Chunks friend UIDs by 10 for `whereIn` queries on `users` collection, persists to local offline cache, and emits `List<UserProfileOnline>`.
     - `getCachedFriends()`, `saveCachedFriends()`: Offline resilience reading and writing friends list to local `Store.instance.note('cached_friends')`.
  5. **Community Routines Hub**:
     - `shareRoutine(Routine routine, {String description = ''})`: Generates unique 6-character code (`GYM-XXXX`, e.g. `GYM-8X2A`) via `_generateShareCode()`, packages routine into `SharedRoutineOnline`, and stores in `shared_routines` collection.
     - `getSharedRoutineByCode(String code)`: Queries `shared_routines` where `code == clean.toUpperCase()`.
     - `streamCommunityRoutines({int limit = 20})`: Real-time stream of recent community routines ordered by `sharedAt` descending.
     - `importSharedRoutine(SharedRoutineOnline shared)`: Unpacks routine JSON, creates local `Routine` instance with fresh ID and attributed author title (`${shared.title} (@${shared.authorHandle})`), inserts into `fit.routines`, and increments remote `downloads` counter via `FieldValue.increment(1)`.
  6. **Zero-Password Account Recovery**:
     - `restoreAccountWithBackupCode(String handle, String backupCode)`:
       - Queries `handles/{cleanHandle}` or `users` collection for account UID and stored backup code.
       - Validates input backup code against stored code (case-insensitive, ignoring hyphens).
       - Restores profile name, handle, badge, biological baselines, units, routines, custom exercises, and weekly plan.
       - Restores friendships: if restoring onto a device with a new anonymous UID, migrates mutual friendship subcollection documents to point to the new UID and transfers handle ownership in `handles` collection.
       - Invokes `fit.completeOnboarding()` and `fit.persistNow()`, then triggers background profile sync.
  7. **GDPR Account Wipe & Cloud Data Purge**:
     - `deleteAccountAndAllData()`: Batch deletes handle claim doc in `handles`, user doc in `users`, all friends subcollection links from both users, incoming/outgoing friend requests, and authored community routines in `shared_routines`.
     - Deletes anonymous Firebase Auth user and creates a fresh anonymous UID for a clean slate.
- **Invariants & Technical Details**: Gracefully falls back to offline operation if network is unavailable or Firebase is not configured.

## 16. Architecture & Data Flow Synthesis

### Cloud Synchronization vs. Local Offline Storage Matrix

| Domain Feature | Local Storage Engine | Cloud Storage (Firebase) | Privacy Boundary | Offline Behavior |
| :--- | :--- | :--- | :--- | :--- |
| **Completed Workouts** | Atomic JSON (`fit_state.json`) | None (Private) | Local-Only | Fully functional |
| **Body Measurements** | Atomic JSON (`fit_state.json`) | None (Private) | Local-Only | Fully functional |
| **Gym Notebook / Notes** | Atomic JSON (`fit_state.json`) | None (Private) | Local-Only | Fully functional |
| **Physique Photos** | `MediaStore` (Private Filesystem) | None (Never Uploaded) | Strictly On-Device | Fully functional |
| **Training Moments** | `MediaStore` (Private Filesystem) | None (Never Uploaded) | Strictly On-Device | Fully functional |
| **Profile Photo & Banner** | `MediaStore` (Private Filesystem) | None (Never Uploaded) | Strictly On-Device | Fully functional |
| **Athlete Handle** | Atomic JSON (`fit_state.json`) | Firestore `handles/{handle}` | Public Unique Index | Cached locally |
| **Account Identity** | `fit.backupCode` (13-char code) | Firestore `users/{uid}` & `handles` | Secret Hash/Token | Cached locally |
| **Public Profile** | Atomic JSON (`fit_state.json`) | Firestore `users/{uid}` | Friends & Search | Cached locally |
| **Friendships & Streaks** | `Store.instance` (`cached_friends`) | Firestore `users/{uid}/friends` | Mutual Friends Only | Cached friends view |
| **Friend Requests** | Transient Stream | Firestore `friend_requests` | Target Athlete Only | Queued when online |
| **Shared Routines** | `fit.routines` (Local Library) | Firestore `shared_routines` | Public (by 6-char code)| Cloned to local library|
| **Gym Equipment Places** | Atomic JSON (`fit_state.json`) | None (Private) | Local-Only | Fully functional |

### Firestore Collections Schema

1. **`handles/{handle}` Collection**:
   - Primary key: Lowercase normalized handle string without `@` (e.g. `iron_athlete`).
   - Fields: `uid` (`String`), `handle` (`String`), `backupCode` (`String`), `claimedAt` (`Timestamp`), `restoredAt` (`Timestamp?`).
   - Managed via atomic transactions (`tx.set`, `tx.delete`) to guarantee handle uniqueness globally.
2. **`users/{uid}` Collection**:
   - Primary key: Anonymous Firebase UID.
   - Fields: `handle`, `displayName`, `badge`, `streak`, `maxStreak`, `weeklyGoal`, `workoutsCompleted`, `lastWorkoutDate`, `backupCode`, `sex`, `age`, `heightCm`, `weightKg`, `units`, `routines` (`List<Map>`), `customExercises` (`List<Map>`), `weeklyPlan` (`Map`), `lastSync` (`Timestamp`).
   - Subcollection `users/{uid}/friends/{friendUid}`:
     - Fields: `friendUid` (`String`), `addedAt` (`String ISO8601`).
3. **`friend_requests/{reqId}` Collection**:
   - Primary key: `${fromUid}_${toUid}`.
   - Fields: `id`, `fromUid`, `toUid`, `fromHandle`, `fromName`, `fromBadge`, `fromStreak`, `status` (`'pending'`), `createdAt` (`String ISO8601`).
4. **`shared_routines/{docId}` Collection**:
   - Primary key: Auto-generated document ID.
   - Fields: `code` (e.g. `GYM-8X2A`), `title`, `description`, `authorUid`, `authorName`, `authorHandle`, `authorBadge`, `daysCount`, `exercisesCount`, `downloads` (`int`), `sharedAt` (`String ISO8601`), `routineData` (`Map<String, dynamic>`).

### Zero-Password Account Recovery Protocol

```text
[ Athlete on New Device ]
          │
          ▼
   Enters @handle + 13-character Backup Code (GYM-XXXX-XXXX)
          │
          ▼
   FirebaseService.restoreAccountWithBackupCode()
          │
          ├── 1. Query Firestore handles/{handle} -> resolves UID & stored backup code
          │
          ├── 2. Validate input code against stored code (case-insensitive, ignoring hyphens)
          │
          ├── 3. Fetch userData from users/{targetUid}
          │       ├── Profile (Name, Handle, Badge, Biological Stats, Units)
          │       ├── Routines & Custom Exercises (Merged into local library)
          │       └── Weekly Schedule & Streak count
          │
          ├── 4. Migrate Social Relationships
          │       ├── Query friends from users/{targetUid}/friends
          │       └── If new UID != targetUid: batch create mutual links to new UID
          │           and transfer handle document ownership to new UID
          │
          └── 5. Persist locally to fit_state.json & Complete Onboarding
```

### Verification & Maintenance Protocol

1. **Static Analysis**: Run `flutter analyze` to ensure 100% compliance with `analysis_options.yaml`.
2. **Automated Test Execution**: Run `flutter test` across all 68 test suites to verify zero regressions.
3. **Asset Verification**: Ensure all 387 ASCII art files in `assets/art/` parse correctly without missing catalog bindings.
4. **Localization Generation**: Run `flutter gen-l10n` after any modifications to `lib/l10n/app_en.arb`.
5. **Firebase Deployment**: Update Firestore security rules in tandem with any modifications to `firebase_service.dart`.
